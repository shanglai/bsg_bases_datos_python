SESION 2.3 - VENTANA
Sintaxis

La misma pregunta, resuelta

SELECT id_transaccion, fecha_hora, monto,
       SUM(monto) OVER (PARTITION BY id_tarjeta ORDER BY fecha_hora) AS acumulado
FROM pagos.transacciones
WHERE estatus = 'APROBADA' AND id_tarjeta = 5
ORDER BY fecha_hora;
La funcion de agregacion es la misma: SUM. Lo que cambia es OVER, que le indica al motor que calcule sobre un conjunto de filas relacionadas y devuelva un valor por cada fila, en lugar de colapsar.
Comprobacion obligatoria: el ultimo acumulado de cada grupo debe coincidir con el total del grupo. Si no coincide, el ORDER BY de la ventana esta mal planteado.

SESION 2.3 - MARCO
La confusion mas frecuente

ORDER BY dentro de OVER no ordena la salida

SUM(monto) OVER (PARTITION BY id_tarjeta)                     -- total del grupo
SUM(monto) OVER (PARTITION BY id_tarjeta ORDER BY fecha_hora) -- acumulado
ExpresionMarco resultanteValor
Sin ORDER BYEl grupo completoEl total, igual en todas las filas
Con ORDER BYDel inicio a la fila actualEl acumulado
Marco explicitoLo que se declareSuma o promedio movil
ORDER BY dentro de OVER cambia el marco, y por lo tanto cambia el valor calculado. No tiene relacion con el ORDER BY final de la consulta.
SESION 2.3 - MARCO
Marco explicito

Promedio movil de tres operaciones

AVG(monto) OVER (PARTITION BY id_tarjeta ORDER BY fecha_hora
                 ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)
ROWSCuenta filas fisicas
RANGEAgrupa las filas con el mismo valor de ORDER BY
El marco predeterminado es RANGE, no ROWS. Un promedio movil escrito sin marco explicito sobre una columna con valores repetidos da un resultado distinto del esperado, y no falla.
Las primeras filas de cada grupo promedian sobre menos de tres operaciones, porque el marco no puede retroceder mas alla del inicio. Es correcto.

SESION 2.3 - RANKING
Desplazamiento

Comparar contra la fila anterior

SELECT mes, importe,
       LAG(importe) OVER (ORDER BY mes) AS mes_anterior,
       ROUND(100.0 * (importe - LAG(importe) OVER (ORDER BY mes))
             / LAG(importe) OVER (ORDER BY mes), 2) AS variacion_pct
FROM por_mes;
LAGLa fila anterior del grupo
LEADLa fila siguiente
FIRST_VALUELa primera del marco
LAST_VALUELa ultima del marco, requiere marco explicito
La primera fila de cada grupo no tiene predecesora y LAG devuelve nulo. Filtrarlo de forma explicita suele ser lo deseado.
SESION 2.3 - LAG Y LEAD
El limite

La ventana no puede usarse en WHERE

SELECT c.ciudad, c.nombre, SUM(t.monto)
FROM ...
WHERE ROW_NUMBER() OVER (PARTITION BY c.ciudad ORDER BY SUM(t.monto) DESC) = 1
GROUP BY c.ciudad, c.nombre;

ERROR: window functions are not allowed in WHERE
La ventana nace en SELECT, que se evalua despues de WHERE, de GROUP BY y de HAVING. Es el mismo orden de evaluacion de la sesion 2.2, un paso mas adelante.
La solucion es calcular en una etapa y filtrar en la siguiente. Esa necesidad es la razon practica de que las CTE y las funciones de ventana se enseñen juntas.
SESION 2.3 - LIMITE
Expresiones de tabla comunes

Nombrar cada paso del calculo

WITH por_comercio AS (
    SELECT c.ciudad, c.nombre, SUM(t.monto) AS importe
    FROM ... GROUP BY c.ciudad, c.nombre
),
ranking AS (
    SELECT *, ROW_NUMBER() OVER (PARTITION BY ciudad
                                 ORDER BY importe DESC) AS posicion
    FROM por_comercio
)
SELECT ciudad, nombre, importe FROM ranking WHERE posicion = 1;
La version con CTE se lee de arriba abajo, en el orden en que ocurre el calculo. La equivalente con subconsultas anidadas se lee de adentro hacia afuera.
SESION 2.3 - CTE
Sobre el desempeno

La CTE mejora la lectura. Y el plan

SituacionEfecto
PostgreSQL 12 y posteriores, una referenciaSe integra en la consulta. Plan equivalente al de una subconsulta
Versiones anterioresBarrera de optimizacion. Se materializaba siempre
Varias referenciasSe materializa una vez y se reutiliza
Se puede forzar con MATERIALIZED y NOT MATERIALIZED.
Lo que conviene retener: la legibilidad mejora siempre; el desempeno depende de la version y del numero de referencias. Afirmar de forma categorica que la CTE es mas rapida o mas lenta es incorrecto.

SESION 2.3 - RECURSIVA
Uso practico

Los meses que no aparecen

WITH RECURSIVE calendario AS (
    SELECT DATE '2026-01-01' AS mes
    UNION ALL
    SELECT (mes + INTERVAL '1 month')::DATE FROM calendario
    WHERE mes < DATE '2026-06-01'
)
SELECT c.mes, COALESCE(p.importe, 0) AS importe
FROM calendario c
LEFT JOIN por_mes p ON p.mes = c.mes;
Un mes sin operaciones no existe en la tabla y por lo tanto no aparece en un GROUP BY. La serie generada garantiza que el periodo quede completo.
El LEFT JOIN va desde el calendario hacia los datos. Invertirlo elimina justamente las filas que se querian conservar.
SESION 2.3 - RECURSIVA
Jerarquias

El otro uso de la recursion

WITH RECURSIVE jerarquia AS (
    SELECT id_area, nombre, 1 AS nivel, nombre::TEXT AS ruta
    FROM areas WHERE id_padre IS NULL              -- caso base
    UNION ALL
    SELECT a.id_area, a.nombre, j.nivel + 1, j.ruta || ' > ' || a.nombre
    FROM areas a JOIN jerarquia j ON j.id_area = a.id_padre   -- paso
)
SELECT nivel, ruta FROM jerarquia ORDER BY ruta;
Aqui la parada es implicita: la recursion termina cuando ninguna fila nueva se agrega, es decir, al agotarse las hojas.
Con un ciclo en los datos, la consulta no termina. Proteccion: UNION en lugar de UNION ALL, un limite de nivel, o la clausula CYCLE.

SESION 2.3 - NEGOCIO
Ventana o dataframe

El mismo calculo, tres lugares posibles

SQLpandasPolars
SUM(x) OVER (PARTITION BY g)groupby(g)[x].transform('sum')col(x).sum().over(g)
SUM(x) OVER (... ORDER BY f)groupby(g)[x].cumsum()col(x).cum_sum().over(g)

En pandas, transform conserva el detalle igual que la ventana; agg colapsa igual que GROUP BY. Confundirlos es el mismo error que abre esta sesion.
Criterio: en el motor cuando el resultado es mucho menor que el origen y hay un solo consumidor. En el dataframe cuando se exploraran varias derivaciones sobre el mismo conjunto.
SESION 2.3 - CRITERIO
Cierre

Lo que queda planteado

  • La ventana calcula sobre un grupo y conserva el detalle
  • El marco decide el valor, y el predeterminado no siempre es el esperado
  • La CTE nombra cada paso y habilita filtrar sobre una ventana
  • La recursion genera series y recorre jerarquias
Pregunta que abre la sesion 2.4: todas estas consultas recorren la tabla completa cada vez, y con cinco mil filas responden de inmediato. Que ocurre con millones de filas, y como se averigua que hace el motor por dentro para resolverlas.
